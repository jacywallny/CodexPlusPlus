# 启动与切换性能

## 验证目标和版本约定

保留跨供应商历史可见性和自动消息索引修复，缩短等待窗口打开的时间。
按用户要求，每轮交付的修复递增一个补丁版本；本轮为 1.5.3。
版本号同时更新 Rust workspace、Cargo.lock、前端 package/lock 和 Tauri 配置。
同一轮内的编译、测试和纠错不产生额外版本号。

## 1.5.3 行为

供应商配置和历史目录可见性同步仍在应用启动前完成；原生消息投影修复在
启动与桥接准备返回后由启动器运行，并沿用每 30 分钟复查。桥接降级时仍在
应用启动之后执行。启动器退出后不安排
新的检查；已开始的索引事务先完成。没有把任务留给脱离启动器的后台进程。

消息索引修复的来源 SHA、数据库写锁后二次检查、备份、事务及回滚均保留。
手动修复入口不变，自动修复开关仍有效。窗口打开后尚未修复的消息投影可能
需要重新打开会话才能显示；对话原文和历史目录不被删除。

新增诊断事件只保存阶段名、版本和汇总时间/计数：运行时准备、供应商同步、
辅助服务准备、应用启动、桥接就绪，以及后台索引检查开始/完成。
不把后台修复时间计入 `launcher.startup.completed`。

## 验收边界

本轮源码和本地语法检查已完成；SSH 构建机 10.6.22.1 当前不可达，Windows
回归、编译和本机安装尚未完成。当前安装仍为 1.5.2。该状态需在交付后更新。

首次缓存构建、真实供应商身份变化时的必要历史改写仍有 IO 成本。
普通重启应复用供应商扫描缓存；是否达到用户期望的快速切换，要用同样的
重启步骤和新增阶段日志确认。没有真实复测前不宣称已经做到秒开。

更进一步的无重启切换需让 Codex 使用固定 provider 标识和本地请求代理，
在代理里切换后端，而不是每次重新初始化应用和迁移历史；官方登录身份、
在途请求和模型兼容性需要独立设计验证。本轮不改变认证或请求路由。
